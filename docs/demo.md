# 本地演示指南

## 一条命令启动

前提：已安装 JDK 21、Node.js、Python 3 和 MySQL 8.4，`java`、`node`、`npm.cmd`、`python`、`mysql.exe`、`mysqld.exe` 在 PATH 中。首次使用 Maven Wrapper 或前端依赖安装需要网络。

在仓库根目录执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/start-demo.ps1
```

脚本先运行后端 `verify`，再按版本号补齐尚未执行的数据库迁移和种子数据，最后启动前后端。显示 `Demo ready` 后打开 <http://127.0.0.1:5180>。在启动终端按 Enter 停止本次进程；不要直接关闭整个终端。

- 演示使用独立 MySQL `13317`、后端 `18081`、前端 `5180`，均只监听本机；不会连接原来的 `3306` 数据库。
- 数据及日志保存于被 Git 忽略的 `.local-demo/`，不放在会被 Maven `clean` 清除的 `target/`；重启保留数据，JWT 密钥仅在启动进程内生成，重启后重新登录。
- 如旧 `backend/target/local-demo/` 仍存在，停止旧演示后启动脚本会整体迁移到 `.local-demo/`。两目录同时存在时会停止，须先人工备份并确认使用哪份，不能覆盖合并 MySQL 数据文件。已经被旧版 `clean` 删除的数据只能从已有备份恢复，脚本不能找回。
- 独立演示 MySQL 使用本机空密码账号，只用于虚构演示数据，不用于生产或个人真实信息。使用现有数据库时按 README 配置环境变量，不运行此脚本。
- 端口已占用时先停止旧演示；迁移失败时查看日志。脚本用本地版本标记保证每个迁移只应用一次；种子 SQL 可重复导入。
- 后端运行包复制到 `.local-demo/backend-demo.jar` 再启动，避免 Windows 构建占用同一 JAR；修改后端后须停止并重新启动演示，页面不会自动加载新后端代码。
- 默认关闭 mock。用户和商家分别现场注册，密码自行设置；种子数据用于浏览和数据库结构展示，不依赖种子账号登录。
- 每次启动通过 `scripts/seed-demo.py` 补充独立库至至少 30 家店铺，并按 `database/init/demo-catalog.json` 仅为初始演示商家的店铺补充餐品和空图片。不会向现场注册商家的空店铺塞入演示商品，不删除订单，不重置已有库存。新增店铺归属初始演示商家，已有店铺的商家归属不变。
- 服务已运行时可单独执行 `python scripts/seed-demo.py`，然后点页面“刷新”。脚本限定本机 `13317` 和本仓库独立数据目录；重复执行不会重复添加同名餐品。手工新增店铺后总数可超过 30，不为凑数删店。
- 首页的六类入口按店名和简介进行关键词搜索；可筛选营业店铺和免配送费，按配送费或起送价排序（营业店铺优先）。商品、价格和库存来自真实接口。

## 管理员初始化

启动演示前，在同一个 PowerShell 终端输入本地虚构管理员信息：

```powershell
$env:ADMIN_USERNAME = Read-Host '演示管理员用户名'
$demoAdminSecure = Read-Host '演示管理员密码（8—72位）' -AsSecureString
$env:ADMIN_PASSWORD = [Net.NetworkCredential]::new('', $demoAdminSecure).Password
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/start-demo.ps1
Remove-Item Env:ADMIN_PASSWORD, Env:ADMIN_USERNAME
```

不要把真实密码粘贴到命令或文件，不截图凭据。登录入口为 <http://127.0.0.1:5180/admin/login>。初始化只创建不存在的用户名，不重置已有账号密码；未设置变量则不创建管理员。演示终止后再清理环境变量。

## 建议演示顺序（四种身份，约 15 分钟）

| 步骤 | 页面与操作 | 展示重点 |
| --- | --- | --- |
| 1 | 登录页进入商家入口，注册并登录商家 | 商家独立身份；首次进入空店铺提示 |
| 2 | 工作台创建“校园演示餐厅”，起送 10 元、配送 3 元 | 店铺新建默认为休息，显示完整金额 |
| 3 | 新增“主食”分类；新增“招牌饭”，售价 30 元、库存 10，添加说明及三张详情图 | 可用本站 `/images/food/rice.jpg`、`/images/food/noodles.jpg`、`/images/food/tea.jpg` |
| 4 | 编辑商品说明、下架后重新上架；停用分类后恢复；发行满 20 减 5 券，有效期包含演示时刻 | 管理列表能找回停用项，券金额和有效期发行后不再改 |
| 5 | 将店铺设为营业，退出商家登录 | 四种身份使用独立账号；切换身份须退出后登录 |
| 6 | 用户入口注册登录；个人信息修改昵称；新增默认地址 | 用户管理、地址管理与持久化 |
| 7 | 找到演示餐厅，领券、查看三张商品图，加购 2 份 | 商品页显示扣除全部购物车占用后的实时可用库存，购物车显示数量及小计 |
| 8 | 进入结算，选地址和券、填备注；进入地址或我的券再返回 | 选择和备注保留；商品 60 − 优惠 5 + 配送 3 = 58 元 |
| 9 | 提交并取消待处理订单，再重新加购 2 份，用返还的券下第二单 | 首次下单库存 8，取消恢复 10，再次下单变 8；取消不会恢复购物车 |
| 10 | 商家订单页刷新，确认后设为制作中；顾客刷新进度 | 接单后顾客不可取消，优惠和收货快照保持一致 |
| 11 | <http://127.0.0.1:5180/rider/login> 注册登录骑手，接单、查看配送信息、取餐、确认送达 | 手机能读地址、电话和备注；电话可唤起拨号，但测试不要真实拨打 |
| 12 | 顾客刷新查看已完成；管理员查询同一单，核对 60 − 5 + 3 = 58 元 | 四身份订单状态与优惠快照一致 |
| 13 | 管理员停用、再启用本次虚构用户与商家，使用另一个浏览器保留的旧会话检查权限 | 禁用后旧会话也被拒绝；恢复后可继续。不要操作其他成员账号 |

追加异常演示：空表单不能提交；未达起送价有明确差额提示；闭店、库存不足不能下单且购物车保留；另一用户不可访问他人订单；重复点击提交或取消不会重复扣减或返还。本项目不接真实支付，金额只代表应付金额。

手机验收使用 390×844，并用 360×800 补查窄屏。检查首页、店铺、商品、购物车、结算、订单、地址和骑手详情：长文字换行、弹窗宽度、按钮不被底栏遮挡、加减容易点击、失败后能重试。结算草稿只在当前登录会话的页面内返回时保留，浏览器整页刷新或退出登录后重置。实体手机软键盘、触摸和弱网仍需人工设备验收，浏览器模拟不等价。

## 可重复的自动检查

需要包含管理员的完整回归时，先按上一节设置管理员环境变量，再启动（也可在 PowerShell 7 直接执行 `& ./scripts/start-demo.ps1 -Verify`）：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/start-demo.ps1 -Verify
```

看到包含“管理员金额快照与账号启停”的检查结果才表示管理员回归已运行。服务已经启动时，在另一个终端执行：

```powershell
python scripts/stage2-smoke.py
python scripts/test-seed-demo.py
```

脚本只用 Python 标准库，核对本仓库 `.local-demo/mysql` 与本机 13317 端口后才写数据。校验 V1—V7 的 14 张表、外键引用、金额、分类归属；复用 stage1 检查注册登录、权限、闭店回滚、订单快照、跨用户购物车占用、库存竞争和默认地址唯一，再检查三图、券核销/返还、重复取消、骑手抢单/越权/送达、种子隔离。管理员分支依赖初始化变量；另开终端未提供时明确报告未运行。

每次创建随机命名的虚构账号、店铺和订单，密码只在内存生成，不输出；验证结束会按本次随机后缀删除这些记录，不影响 30 家初始店铺和手工数据。脚本只允许连接本仓库的独立演示库，不要在生产库运行。

后端测试与覆盖率：`backend/target/site/jacoco/index.html`，`verify` 对每个顶层 Service 设置行/方法 90% 检查；这不代表接口覆盖率或所有边界都已验证。启动日志在 `.local-demo/`，HTTP 检查结果输出在终端。测试可能产生包含请求头的失败日志，不将原始日志直接上传，PR 只记录已脱敏的计数与结果。人工演示由三人核对页面和结果，不将自动检查冒记为人工交叉验收。
