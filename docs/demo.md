# 本地演示指南

## 一条命令启动

前提：已安装 JDK 21、Node.js、Python 3 和 MySQL 8.4，`java`、`node`、`npm.cmd`、`python`、`mysql.exe`、`mysqld.exe` 在 PATH 中。首次使用 Maven Wrapper 或前端依赖安装需要网络。

在仓库根目录执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/start-demo.ps1
```

脚本先运行后端 `verify`，再按版本号补齐尚未执行的数据库迁移和种子数据，最后启动前后端。显示 `Demo ready` 后打开 <http://127.0.0.1:5180>。在启动终端按 Enter 停止本次进程；不要直接关闭整个终端。

- 演示使用独立 MySQL `13317`、后端 `18081`、前端 `5180`，均只监听本机；不会连接原来的 `3306` 数据库。
- 数据及日志保存于被 Git 忽略的 `backend/target/local-demo/`；重启保留数据，JWT 密钥仅在启动进程内生成，重启后重新登录。
- 独立演示 MySQL 使用本机空密码账号，只用于虚构演示数据，不用于生产或个人真实信息。使用现有数据库时按 README 配置环境变量，不运行此脚本。
- 端口已占用时先停止旧演示；迁移失败时查看日志。脚本用本地版本标记保证每个迁移只应用一次；种子 SQL 可重复导入。
- 默认关闭 mock。用户和商家分别现场注册，密码自行设置；种子数据用于浏览和数据库结构展示，不依赖种子账号登录。
- 每次启动通过 `scripts/seed-demo.py` 补充独立库至至少 30 家店铺，并按 `database/init/demo-catalog.json` 补充餐品。已有店铺、订单与手工修改的商品不删除、不重置库存；仅为空的店铺图片补充本地配图。新增店铺归属初始演示商家，已有店铺的商家归属不变。
- 服务已运行时可单独执行 `python scripts/seed-demo.py`，然后点页面“刷新”。脚本限定本机 `13317` 和本仓库独立数据目录；重复执行不会重复添加同名餐品。手工新增店铺后总数可超过 30，不为凑数删店。
- 首页的六类入口按店名和简介进行关键词搜索；可筛选营业店铺和免配送费，按配送费或起送价排序（营业店铺优先）。商品、价格和库存来自真实接口。

## 建议演示顺序（约 10 分钟）

| 步骤 | 页面与操作 | 展示重点 |
| --- | --- | --- |
| 1 | 登录页进入商家入口，注册并登录商家 | 商家独立身份；首次进入空店铺提示 |
| 2 | 工作台创建“校园演示餐厅”，起送 10 元、配送 2 元 | 店铺新建默认为休息，显示完整金额 |
| 3 | 新增“主食”分类；新增“招牌饭”，售价 12.50 元、库存 10 | 分类、价格、库存管理 |
| 4 | 编辑商品说明、下架后重新上架；停用分类后恢复 | 管理列表仍可找到停用/下架数据；刷新后持久保存 |
| 5 | 将店铺设为营业，退出商家登录 | 营业/休息/临时闭店管理 |
| 6 | 用户入口注册登录；个人信息修改昵称；新增默认地址 | 用户管理、地址管理与持久化 |
| 7 | 找到演示餐厅，选择招牌饭，加购 2 份 | 实时库存、购物车数量及小计 |
| 8 | 进入结算，选择地址，核对商品 25 元 + 配送 2 元并提交 | 订单总金额 27 元；成功后购物车清理 |
| 9 | 查看订单列表和详情，刷新页面后重新查看 | 订单号、待处理状态、商品与收货快照 |
| 10 | 退出用户，重新登录商家，查看库存 8 | 前后端、真实 MySQL、库存事务闭环 |
| 11 | 商家打开“处理订单”，确认订单并开始制作 | 订单状态待处理→已确认→制作中 |
| 12 | 骑手入口注册并登录，在“待接订单”接单，随后“已取餐”“确认送达” | 制作中订单进入待接池；接单归属、配送流转 |
| 13 | 管理员入口登录（账号由 ADMIN_USERNAME/ADMIN_PASSWORD 环境变量初始化），查看用户/商家/店铺/订单列表，停用并恢复一名用户 | 管理员四类查询；停用后该用户无法登录，启用后恢复 |
| 14 | 顾客回到订单详情，查看“已完成”终态；管理员订单列表同步显示 | 全链路状态一致 |

追加异常演示：空表单不能提交；商家将店铺设为休息后用户下单失败，购物车保留；另一用户不可访问前一用户的订单；管理员停用账号后旧 Token 立即失效。基础订单演示完整接单流转；取消订单恢复库存，但不演示真实支付。

## 可重复的自动检查

演示服务启动后，在另一个终端执行：

```powershell
python scripts/stage1-smoke.py http://127.0.0.1:5180/api/v1
```

脚本使用 Python 标准库，通过前端代理访问真实接口，创建随机命名的虚构商家和用户；密码仅在内存生成，不输出。验证注册登录、管理查询、个人信息、权限、闭店回滚、下单库存/清理、删除地址后的订单快照、并发库存及默认地址唯一。脚本会留下测试记录，只在独立测试库运行。

后端测试与覆盖率：`backend/target/site/jacoco/index.html`。脚本启动日志与验证结果在 `backend/target/local-demo/`。人工演示时由三人核对页面和结果，不将自动化检查冒记为人工交叉验收。
