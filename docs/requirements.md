# 需求文档

> 版本：1.0（2026-09-14）
> 本文档描述 elm-lite-platform（校园外卖服务平台）的需求范围、业务规则与验收标准，供开发、测试与验收使用。接口细节以 `api-contract.md` 为准，数据字段以 `docs/database/data-dictionary.md` 与 `docs/database/er-diagram.md` 为准。

## 1. 项目概述

### 1.1 背景与目标

参照饿了么核心业务流程，构建一套轻量级、前后端分离的校园外卖服务平台。项目以 TDD（测试驱动开发）、REST 接口和 Git 协作为工程重点，交付一套可演示、可测试、可迭代的系统。

### 1.2 系统范围

本系统支持四种身份在一个平台内协作完成外卖点餐全流程：

- 顾客：浏览店铺与商品、管理地址与购物车、下单、跟踪订单、领券与用券。
- 商家：注册账号、创建店铺、管理分类与商品、发行优惠券、处理订单（确认、开始制作）。
- 骑手：注册账号、查看待接订单、接单、取餐、配送、确认送达。
- 管理员：由环境变量初始化账号，查询用户/商家/店铺/订单，启用/停用用户与商家账号。

### 1.3 技术约束

- 后端：JDK 21、Spring Boot、Maven、MyBatis-Plus、MySQL；分层为 Controller/Service/Mapper/Entity，统一 `/api/v1` 前缀与 `code/msg/data` 响应结构。
- 前端：Vue 3、Vue Router、Axios、Element Plus；支持手机（约 390×844）与桌面两种布局。
- 测试：JUnit 5、MockMvc、H2（MySQL 兼容模式）、JaCoCo 覆盖率。
- 金额一律以整数“分”存储与传输，前端按“元”显示。

## 2. 用户角色与权限

| 角色 | 获取方式 | 主要权限 |
| --- | --- | --- |
| 顾客（USER） | 注册登录 | 店铺/商品浏览、地址、购物车、下单与取消、订单查询、领券用券 |
| 商家（MERCHANT） | 注册登录 | 店铺/分类/商品/优惠券管理、查看并处理本店订单 |
| 骑手（RIDER） | 注册登录 | 查看待接订单、接单、取餐、配送、送达；仅能操作归属自己的任务 |
| 管理员（ADMIN） | 环境变量初始化 | 用户/商家/店铺/订单查询，用户与商家账号启停 |

鉴权使用 JWT，令牌携带账号身份；接口按身份校验，非本人资源一律拒绝（越权返回 403）。管理员接口匿名访问返回 401，非管理员令牌返回 403。被停用账号登录被拒绝，且其已签发令牌立即失效。

## 3. 功能需求

### 3.1 用户注册、登录与个人信息

- 顾客可注册（用户名、密码 8–72 位、昵称）并登录；登录成功签发身份令牌。
- 登录失败不区分“账号不存在”与“密码错误”，统一返回同一提示，防止账号枚举。
- 顾客可查看和修改本人昵称；被停用账号登录返回“账号已禁用”。

### 3.2 收货地址

- 顾客可新增、查询、修改、删除本人地址；字段含收货人、电话、详细地址、标签、是否默认。
- 同一用户最多一个默认地址，设置新默认时原默认自动取消。
- 删除默认地址不影响历史订单快照。

### 3.3 店铺浏览与商品

- 未登录可浏览店铺列表、店铺详情、分类与商品；列表支持关键词搜索、营业/免配送费筛选、按配送费或起送价排序。
- 商品公开展示：名称、描述、图片（封面与最多 3 张详情图）、价格、可用库存、上架状态；可用库存为数据库库存减去全部用户购物车占用，最低显示 0，商家管理端仍显示数据库实际库存；下架或停用分类下商品不出现在公开列表。
- 商品详情展示大图、缩略图、介绍、价格、库存、所属店铺与底部购买栏（数量选择、加入购物车）。

### 3.4 购物车

- 顾客可加购、修改数量、删除购物车明细；明细含商品名称、单价、数量、小计。
- 不同店铺商品不得混入同一结算单；跨店加购时购物车校验并提示。
- 购物车数量会临时占用可售库存；跨用户占用合计不能超过数据库库存。购物车实时反映数据库库存与上架状态（售罄/下架提示）。

### 3.5 下单与结算

- 结算页展示收货地址、商品清单（可勾选）、商品小计、配送费、优惠金额、合计、备注。
- 顾客可领取并使用商家优惠券；结算时按门槛与金额自动判定可用券，选择后实时重算金额。
- 下单校验：店铺营业、地址存在、商品上架且库存充足；校验失败不下单且购物车保留。
- 下单成功后：生成订单快照（商品、金额、收货信息）、扣减库存、清理对应购物车明细、核销所选优惠券。

### 3.6 订单生命周期与取消

订单状态机：待处理 → 已确认 → 制作中 → 配送中 → 已完成；另有已取消。

- 顾客：查看订单列表与详情（商品、金额、收货快照）；仅可取消“待处理”订单。
- 取消订单：恢复商品库存；若使用了优惠券则原券退回且不重复返还；重复取消与并发取消被拒绝。
- 商家：查看本店订单列表（状态筛选）与详情，确认订单、开始制作；不得操作他人店铺订单。
- 骑手：查看制作中订单池，原子接单（并发下仅一人成功）、取餐、配送、确认送达；只能操作本人任务，重复送达被拒绝。

### 3.7 优惠券

- 商家可创建优惠券（满减金额、门槛、有效期）；创建后金额/门槛/有效期不可修改，只能启用或停用。
- 顾客可查看店铺优惠券并领取；同一用户同一券不可重复领取；过期券不可领取与使用。
- 结算选券：按店铺与订单金额过滤可用券；用券后订单记录优惠快照，历史订单金额不随券变化。
- 取消订单返券，且不重复返还。

### 3.8 商家管理

- 商家可创建店铺（名称、地址、简介、起送价、配送费）并设置营业状态（营业/休息/临时闭店）。
- 商家可管理分类（名称、排序、启停）与商品（名称、分类、描述、封面与详情图、售价、库存、上下架）。
- 店铺设为休息时顾客不可下单；闭店不影响已生成订单。

### 3.9 骑手端

- 骑手注册（账号、密码、姓名）与登录。
- 待接订单列表展示制作中的订单；接单后进入“我的任务”，依次执行取餐、配送、送达。
- 接单归属不可转移；未登录或非骑手身份访问骑手接口返回 401/403。

### 3.10 管理端

- 管理员账号由 `ADMIN_USERNAME`/`ADMIN_PASSWORD` 环境变量在服务启动时初始化（凭据不入库日志、不出现在响应）。
- 查询用户、商家、店铺、订单四类列表：支持关键字与状态筛选；响应不暴露密码哈希与联系方式等敏感字段。
- 查看订单详情：顾客、地址、备注、商品明细、金额构成。
- 启用/停用用户与商家账号：状态非法返回 400，目标不存在返回 404；停用立即生效。

### 3.11 页面体验要求

- 每个页面提供加载中、空数据、校验与错误提示；提交类操作提供确认与成功/失败反馈。
- 手机（约 390×844）布局：顶部导航、底部四栏导航（首页/店铺/订单/我的）、安全区适配；无横向溢出、按钮不遮挡、图片不变形。
- 桌面（约 1440×900）布局完整可用。

## 4. 非功能需求

- **安全**：密码 BCrypt 存储；JWT 鉴权；越权与水平越权全覆盖拒绝；不输出密码、令牌等敏感信息。
- **事务一致性**：下单（库存扣减、购物车清理、券核销）与取消（库存恢复、返券）为单事务；失败回滚。
- **并发**：库存扣减、骑手接单、券领取/核销在并发下不超扣、不重复；相关接口经并发测试。
- **性能**：列表接口索引化查询，演示环境页面加载流畅。
- **可测试性**：后端关键业务有自动化测试覆盖，前端页面有组件/工具级测试与生产构建。
- **可部署性**：提供一条命令本地演示脚本（独立 MySQL、后端、前端）与部署文档。

## 5. 业务边界（明确不实现）

- 不接真实支付、退款渠道；金额仅为演示数据。
- 不实现配送路径规划与实时定位；骑手操作按状态流转。
- 不实现店铺评分、评价、IM 沟通等扩展功能。
- 演示数据仅用于课程演示，不包含真实个人信息。

## 6. 数据与接口概要

- 数据表：用户、商家、店铺、商品分类、商品、购物车明细、收货地址、订单、订单明细、优惠券、用户券、骑手、管理员（详见 `docs/database/data-dictionary.md` 与 ER 图）。
- 接口：统一 `code/msg/data` 响应；`/api/v1` 前缀；四类身份的登录与资源接口（详见 `api-contract.md`）。
- 订单金额 = 商品小计 + 配送费 − 优惠金额；全部以分为单位，历史订单保存下单时快照。

## 7. 验收标准

1. 后端全量测试通过，核心业务（订单、优惠券、商品、库存）覆盖率达标。
2. 前端测试通过且生产构建成功。
3. 四身份真实走查：顾客下单 → 商家确认/制作 → 骑手接单/送达 → 管理员终态一致；取消订单恢复库存并返券。
4. 手机与桌面页面无横向溢出，图片不变形，交互反馈完整。
5. 演示视频包含一个完整的下单流程（浏览、加购、结算、下单、商家处理、骑手配送）。
6. 仓库公开，`docs/` 含本需求文档与部署文档，文档中不含组号与组员信息。
